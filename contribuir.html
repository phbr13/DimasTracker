Guia de contribuição

Como contribuir?

O DimasTracker é feito por estudantes, para estudantes. Achou um gabarito errado, resolveu um exercício que ainda não tem solução ou teve uma ideia para o site? Toda ajuda conta — e você não precisa saber programar para várias delas.

1 Jeitos de ajudar

Reportar um erro Conta errada, enunciado trocado, PDF que não abre. Leva 2 minutos. Sem programação Escrever um gabarito Resolva em Markdown com fórmulas em LaTeX; a ferramenta faz o resto. Markdown + LaTeX Adicionar um exercício Um item novo na lista, com o PDF do enunciado. Um pouco de terminal Melhorar o site Novos recursos, correções de bugs, acessibilidade, visual. HTML, CSS e JS

2 Reportar um erro

O jeito mais rápido de ajudar. Você só precisa de uma conta (gratuita) no GitHub.

  1. Abra uma issue — é como um “chamado” no GitHub. Abrir uma issue ↗
  2. Escolha o modelo “Erro em gabarito” ou “Sugestão”.
  3. Diga onde está o problema: a prova, o item (ex.: Prova 2 · 4.1.7) e o que está errado. Se souber a resposta certa, melhor ainda!
Dica: antes de abrir, dê uma olhada nas issues abertas — talvez alguém já tenha relatado o mesmo problema. Nesse caso, deixe um 👍 nela.

3 Preparar o ambiente

Para mexer nos arquivos, você vai precisar de:

  • Git e uma conta no GitHub — baixar o Git
  • Node.js (versão 18 ou mais nova) — só para gerar gabaritos · nodejs.org
  • Python 3 — só para adicionar PDFs de exercícios · python.org
  1. Faça um fork: no repositório, clique em Fork. Isso cria uma cópia do projeto na sua conta.
  2. Baixe a sua cópia (troque SEU-USUARIO pelo seu usuário): 
    git clone https://github.com/SEU-USUARIO/DimasTracker.git
cd DimasTracker
  3. Crie um branch para a sua mudança: 
    git checkout -b gabarito-4.1.7
  4. Abra o site: é só dar dois cliques no index.html. Não tem build, não tem servidor — é HTML, CSS e JavaScript puros. Se preferir um servidor local: 
    npm run servir

4 Escrever um gabarito

Os gabaritos são escritos em Markdown com fórmulas em LaTeX e depois convertidos para o formato que o site carrega. Você escreve texto normal; as contas ficam entre cifrões.

  1. Instale as dependências (só na primeira vez): 
    npm install
  2. Copie o modelo fontes/MODELO.md para fontes/Prova N/<item>.md. O nome do arquivo precisa ser exatamente o texto do item na lista — por exemplo fontes/Prova 1/1.1.10 (a,c).md.
  3. Escreva a solução. Um exemplo curto: 
    # Exercício 1.1.1 — Gabarito

**Enunciado.** Calcule $AB - BA$ para as matrizes dadas.

## (a) $AB - BA$

$$
AB - BA = \begin{bmatrix} -24 & -20 \\ 58 & 24 \end{bmatrix}
$$

> **Resposta:** $AB \neq BA$, o produto não é comutativo.
  4. Gere o gabarito: 
    npm run gabaritos
    Isso cria gabaritos/Prova N/<item>.js. Se alguma fórmula tiver erro de LaTeX, a ferramenta avisa qual é.
  5. Confira no site: recarregue o index.html e clique no item.

Fórmula em destaque$$ \det(A) = ad - bc $$

Resposta final> **Resposta:** ...
Imagem![esboço](figuras/fig_7_2_1.png)
Imagens: salve em gabaritos/Prova N/figuras/ e use o caminho relativo figuras/arquivo.png. Prefira PNG com fundo branco — o site mostra imagens sobre um cartão claro.
Corrigindo um gabarito antigo? Os gabaritos que já existem foram gerados sem arquivo-fonte. Para corrigir um deles, reescreva-o em fontes/ (pode copiar o texto do site) e gere de novo — o .js antigo é substituído.

5 Adicionar um exercício

  1. Coloque o PDF do enunciado em exercicios/Prova N/<item>.pdf.
  2. Adicione o item na lista, no topo do script.js, com o mesmo texto do nome do arquivo: 
    const provas = {
  2: [
    "3.2.7", "3.2.9", "3.2.13", ...
  3. Gere as páginas que o visualizador mostra (converte o PDF em imagens nítidas e preserva os marca-textos): 
    py -m pip install pymupdf      # só na primeira vez
py ferramentas/gerar-paginas.py
    No macOS/Linux, use python3 no lugar de py.
  4. Escreva o gabarito seguindo a seção anterior (opcional, mas muito bem-vindo).

6 Melhorar o site

O site é propositalmente simples. Algumas combinações para manter assim:

  • Sem build e sem frameworks. HTML, CSS e JavaScript puros, que funcionam abrindo o arquivo direto (file://) e no GitHub Pages.
  • Código em português, como o resto do projeto: mostrarProva, .gabarito-area.
  • Cores só por variáveis (--fundo, --texto…) definidas no topo do style.css, para os temas claro e escuro funcionarem.
  • Teste nos dois temas e com as seções redimensionadas antes de enviar.
  • Mudanças pequenas e focadas são revisadas (e aceitas) muito mais rápido.

7 Enviar a contribuição

  1. Salve as mudanças com uma mensagem clara: 
    git add .
git commit -m "Adiciona gabarito do 4.1.7"
git push origin gabarito-4.1.7
  2. Abra um Pull Request: o GitHub mostra um botão Compare & pull request no seu fork. Descreva o que mudou.
  3. Aguarde a revisão. Pode ser que peçam um ajuste — é normal e faz parte. Assim que for aceito, a mudança vai ao ar sozinha no site em alguns minutos.
